# Social Network: учебный монолит

## Цель
Скелет социальной сети: регистрация, логин, просмотр анкеты по ID.
Эндпоинты: `POST /login`, `POST /user/register`, `GET /user/get/{id}`.
Контракт описан в `docs/openapi.json` и является источником истины.

## Архитектура
- `packages/core`: общий composer-пакет, только бизнес-логика
  (Domain и Application, включая интерфейсы портов). Никакой инфраструктуры.
- `apps/native`: чистый PHP. Свои Infrastructure и Presentation, свой composition root.
- `apps/symfony`: Symfony. Свои Infrastructure и Presentation, своя конфигурация DI.
- `frontend/`: статический UI (HTML + ES-модули, без сборки) для ручной проверки API.
  Ходит в оба приложения через `nginx-frontend` (dev-only), контракт не меняет.
- `social-network-docker/`: Dockerfile'ы и конфиги php-fpm, nginx, postgres.
  `docker-compose.yaml` и `.env` лежат в корне репозитория.
- `db/migrations/`: общая SQL-схема для обоих приложений.
- Реализации портов (PDO-репозиторий, хешер, токены) пишутся в каждом приложении
  отдельно, но обязаны проходить одни и те же contract-тесты из `core/tests/Contract`.
- Оба приложения дают идентичный HTTP-контракт на одной БД
  для честного нагрузочного сравнения.
- Приложения не зависят друг от друга. Общий код только через `core`.

## Стандарты кода
- PHP 8.4+, `declare(strict_types=1)` в каждом файле.
- SOLID, Clean Architecture, зависимости направлены внутрь (к Domain).
- Dependency injection, без статических вызовов и глобального состояния.
- Value objects и immutable-объекты там, где это уместно.
- Интерфейсы для всего, что пересекает границу слоя.
- Осмысленные имена, без аббревиатур и суффиксов-мусора.
- Без фреймворк-специфичных shortcut'ов в общем коде.

## Жёсткие ограничения задания
- Без ORM. Только PDO с параметризованными запросами (prepared statements).
  Конкатенация пользовательских данных в SQL запрещена.
- Пароли только через `password_hash` (argon2id), в открытом виде не хранить и не логировать.
- Не использовать репликацию, шардирование, кэширование.
- Индексы не добавлять сверх первичного ключа и ограничений, нужных для корректности.
- Монолит: никаких отдельных сервисов, очередей, брокеров.

## Правила работы
- Код пишем только по явной просьбе. Сначала обсуждаем дизайн.
- Не добавлять зависимости без согласования.
- Любое изменение контракта сначала вносится в `docs/openapi.json`,
  затем реализуется в обоих приложениях.
- Любая новая реализация порта сначала получает contract-тест в `core`,
  затем реализуется в обоих приложениях.
- Изменение схемы БД: сначала `db/migrations`, затем оба репозитория.
- Реализации Infrastructure в обоих приложениях эквивалентны по подходу
  (PDO, prepared statements, argon2id, одинаковые параметры хеширования),
  чтобы нагрузочный тест сравнивал фреймворки, а не разные реализации.
- Любое изменение в `core` не должно ломать оба приложения.
- Нагрузочные замеры только в режиме bench (`make bench-up`): одинаковые лимиты
  ресурсов, `php.ini`, `php-fpm.conf`, без bind mount.

## Команды
Определены в `Makefile`, список: `make help`.

## Definition of Done
- Регистрация, логин и получение анкеты работают в обоих приложениях.
- Unit-тесты `core` проходят.
- Postman-коллекция проходит против обоих приложений.
- README содержит инструкцию по локальному запуску.
