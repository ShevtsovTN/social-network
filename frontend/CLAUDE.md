# frontend: клиент для проверки API

## Роль
Простой UI поверх HTTP-контракта из `docs/openapi.json`: регистрация, вход, анкета по id.
Переключатель backend'а (native / Symfony) нужен, чтобы вручную убедиться, что оба приложения
дают идентичный контракт. Бизнес-логики здесь нет, валидация на сервере.

## Состав
- `index.html`, `css/styles.css`: страница и стили (светлая и тёмная темы).
- `js/main.js`: hash-роутер (`#/register`, `#/login`, `#/user/<id>`), выбор backend'а, панель сессии.
- `js/api.js`: клиент контракта и `ApiError` (`status`, `message`, `field`).
- `js/session.js`: backend в `localStorage`, сессия (`userId`, токен) в `sessionStorage` и в памяти.
- `js/form.js`: поля формы, тексты ошибок по `field`, обработка отправки.
- `js/views/`: экраны регистрации, входа и анкеты.
- `js/dom.js`: `el()`, создание элементов без `innerHTML`.

## Правила
- Без сборки и без зависимостей: чистый HTML, CSS и ES-модули. Новые зависимости только по согласованию.
- Данные пользователей выводятся только через текстовые узлы (`el()`/`textContent`), никакого `innerHTML`.
- Пароль нигде не сохраняется и не логируется. Токен непрозрачный, клиент его не разбирает.
- На клиенте только лёгкие ограничения из openapi (`required`, `maxlength`); источник истины валидации сервер.
- Запросы идут на тот же origin: `/api/<backend>/...` проксирует `nginx-frontend`. CORS в приложениях не нужен
  и добавляться не должен (это изменение контракта).
- `nginx-frontend` определён только в `docker-compose.override.yaml`, в bench-режим не входит.
- Интерфейс на русском; сообщения сервера показываются как есть мелким текстом.
- Автотестов UI нет, проверка вручную (см. README).
